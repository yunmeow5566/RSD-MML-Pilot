# SOLID Principles
There are plenty of materials online like [this](https://dev.to/mstuttgart/understanding-solid-principles-a-beginners-guide-4fl6) to explain the *SOLID* principles. 

Beginners can start with the first one, *Single Responsibility*, which can guide us to modularize our code more effectively. In general, if we see a function name that includes the word *and*, it usually means this function can be split into smaller and more focused functions.

The second one, *Open–Closed Principle*, is a valuable practice to integrate into day‑to‑day development. Note that we should use unit tests to guard existing functionality and avoid unintended breaking changes.
